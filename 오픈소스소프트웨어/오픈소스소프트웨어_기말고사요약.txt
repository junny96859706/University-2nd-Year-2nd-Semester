<1. 브랜치(Branch)와 HEAD의 개념>
- 브랜치(Branch): 기존 코드에 영향을 주지 않고 독립적으로 작업하기 위한 작업 흐름 (커밋을 가리키는 가벼운 포인터)
- HEAD: "지금 내가 위치한 브랜치"를 가리키는 현재 위치 표시 포인터
- 핵심: 새로운 커밋은 항상 현재 HEAD가 가리키는 브랜치에 추가됨


<2. 브랜치 생성 및 전환 (git branch, git switch)>
# 현재 브랜치 목록 확인 (* 표시가 현재 위치)
git branch

# 새 브랜치 생성 (전환은 하지 않음)
git branch devel

# 브랜치 전환 (checkout 대신 최신 switch 명령 사용)
git switch devel

# 브랜치 생성과 동시에 전환 (자주 사용)
git switch -c feature/login

# 브랜치 이력 그래프로 한눈에 조회
git log --oneline --graph --all


<3. 병합(Merge)의 종류: Fast-forward vs 3-way Merge>
- Fast-forward 병합:
  * 이력이 일직선일 때 발생 (main에 새 커밋이 없는 상태)
  * 별도의 병합 커밋을 만들지 않고 main 포인터만 앞으로 이동
  * --no-ff 옵션: 일직선이어도 강제로 병합 커밋(M)을 남김 (git merge --no-ff devel)
- 3-way 병합:
  * 두 브랜치의 이력이 서로 갈라졌을 때 발생
  * 두 브랜치의 끝 커밋(C4, C5)과 '공통 조상(C3)' 3가지를 비교하여 병합
  * 병합 성공 시 부모 커밋을 2개 가지는 '병합 커밋(Merge Commit)'이 새로 생성됨


<4. 병합 충돌(Merge Conflict) 해결 4단계>
- 충돌 발생 조건: 두 브랜치가 같은 파일의 같은 줄을 서로 다르게 수정한 경우
- 1단계 (확인): git status 명령어로 충돌 파일 확인
- 2단계 (수정): 파일 내 충돌 마커(<<<<<<<, =======, >>>>>>>)를 포함해 원하는 내용만 남기고 모두 삭제
- 3단계 (표시): git add <파일명> (스테이징이자 충돌 해결 완료 표시)
- 4단계 (완료): git commit 명령으로 병합 커밋 생성
* 병합 취소: git merge --abort (병합 시도 전 상태로 완전 복원)


<5. 브랜치 정리 및 원격 브랜치>
# 이미 병합 완료된 브랜치 안전 삭제
git branch -d devel

# 병합되지 않은 브랜치 강제 삭제
git branch -D experiment

# 원격 저장소에 브랜치 push 및 pull
git push -u origin devel
git fetch                     # 원격 저장소의 최신 브랜치 정보 가져오기
git push origin --delete devel # 원격 저장소의 브랜치 삭제


<6. 실수 되돌리기 (amend, restore, reset, revert)>
- git commit --amend: 직전 커밋 메시지 수정 또는 파일 누락 수정 (커밋 해시가 변경되므로 push 전만 사용)
- git restore <파일>: 작업 디렉터리의 수정을 취소하고 마지막 커밋 상태로 복원
- git restore --staged <파일>: 스테이징 영역(Staging Area)에 올라간 파일 내리기
- git reset <커밋>: 브랜치 포인터를 과거 커밋으로 되돌림 (이력 삭제/조작)
  * --soft: 커밋만 취소 (변경 파일은 Staged 상태 유지)
  * --mixed (기본값): 커밋+스테이징 취소 (변경 파일은 Unstaged 유지)
  * --hard: 모든 변경 사항과 파일 수정을 영구 삭제 후 복원 (주의)
- git revert <커밋>: 지정한 커밋의 변경 사항을 '반대로 적용한 새 커밋'을 생성 (이력 유지, 이미 push 한 커밋 되돌릴 때 사용)
* 판단 기준: push 전이면 reset/amend 사용 가능, 이미 push 한 후면 반드시 revert 사용!


<7. 작업 임시 저장 (git stash)>
- 용도: 미완성된 작업을 커밋하지 않고 임시 보관함에 치워둔 뒤 다른 브랜치로 전환할 때 사용
git stash        # 현재 작업 내용 임시 보관
git stash list   # 보관함 목록 확인
git stash pop    # 보관된 작업 꺼내서 적용 후 목록에서 제거
