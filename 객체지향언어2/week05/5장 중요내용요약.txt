[Java 5장: 상속(Inheritance) 핵심 요약 노트]

1. 상속 기본 개념
- 키워드: extends
- 자바는 '단일 상속(Single Inheritance)'만 지원 (부모 클래스는 오직 1개만 가능)
- 부모를 명시하지 않은 모든 클래스는 최상위 클래스인 java.lang.Object를 자동 상속함

2. protected 접근 지정자
- 같은 패키지 내부 접근 허용
- 다른 패키지에 있더라도 '상속관계의 자식 클래스'라면 접근 허용

3. 상속에서의 생성자 체이닝 (Constructor Chaining)
- 객체 생성 시 실행 순서: 부모 생성자 -> 자식 생성자
- 자식 생성자 첫 줄에는 기본적으로 super(); (부모 기본생성자 호출)가 자동 삽입됨
- ⚠️ 부모 클래스에 매개변수가 있는 생성자만 존재할 경우:
  자식 생성자 첫 줄에서 반드시 super(값);을 명시적으로 호출해야 컴파일 에러가 나지 않음

4. 업캐스팅(Upcasting) & 다운캐스팅(Downcasting)
- 업캐스팅: 자식 객체를 부모 타입 변수에 담는 것 (자동 형변환)
  * 업캐스팅 시 부모 클래스에 정의된 멤버만 접근 가능
- 다운캐스팅: 업캐스팅된 객체를 다시 원래 자식 타입으로 돌리는 것 (명시적 형변환 (Student)p 필요)
  * 원래 자식 객체가 아니었던 부모 객체를 강제 다운캐스팅하면 ClassCastException 발생
- instanceof 연산자: 객체가 특정 클래스의 인스턴스가 맞는지 안전하게 확인 (p instanceof Student)

5. 메서드 오버라이딩(Overriding) & 동적 바인딩
- 오버라이딩: 부모에게 물려받은 메서드를 자식이 재정의(덮어쓰기)하는 것
  * 조건: 메서드 이름, 매개변수, 리턴 타입이 모두 완전히 같아야 함
- @Override 어노테이션: 오타 방지 및 컴파일러 에러 체크용 (필수는 아니지만 권장)
- 동적 바인딩 (Dynamic Binding) 원리:
  * 업캐스팅 상태에서 오버라이딩된 메서드를 호출하면, 부모의 메서드가 아닌 자식의 메서드가 실행됨
  * 원인: 컴파일 타임에는 변수 타입만 확인하지만, 실행(Run-time) 시 JVM이 힙 영역에 있는 실제 객체의 '가상 메서드 테이블(VMT)'을 참조하여 덮어씌워진 자식의 메서드 메모리 주소를 호출하기 때문

추상 클래스의 필드(변수)에는 abstract 키워드를 붙이지 않으며, 붙여서도 안된다.

-오버라이딩 시 접근 지정자는 부모와 같거나 더 넓은 범위로만 바꿀 수 있다. 
(좁히는 것은 컴파일 에러!!!!)

6. 추상 클래스 (Abstract Class)
- 키워드: abstract class / abstract 메서드
- 미완성 메서드(몸체 {}가 없는 메서드)를 포함하는 클래스
- new 키워드로 단독 객체 생성 불가
- 서브클래스가 부모의 추상 메서드를 모두 오버라이딩(구현)하면 abstract를 떼고 new로 객체 생성이 가능한 일반 클래스가 됨 (만약 구현 안 하면 서브클래스도 abstract 붙여야 함)

7. 인터페이스 (Interface)
- 키워드: interface / implements
- 완전한 추상 틀 (규격서)
- 모든 변수: 자동으로 public static final (상수)
- 모든 메서드: 기본적으로 public abstract (추상 메서드)
- new 키워드로 단독 객체 생성 불가
- 다중 구현 가능: 클래스는 단일 상속만 되지만, 인터페이스는 여러 개를 동시에 implements 가능
-인터페이스는 필드(멤버변수)를 만들수 없다!
