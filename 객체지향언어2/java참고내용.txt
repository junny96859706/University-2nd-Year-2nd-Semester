[Eclipse] 코드 복사 시 렉(로딩 지연) 원인 및 해결법
==================================================

1. 원인
  - 이클립스는 코드를 복사할 때 텍스트뿐만 아니라 
    색상, 폰트 등 서식 정보(HTML/RTF)를 함께 클립보드에 저장함.
  - 이를 웹 입력창에 붙여넣을 때 브라우저가 서식을 해석하느라 
    로딩 지연(렉)이 발생함.

2. 해결 방법 (가장 빠르고 확실한 방법)
  - 붙여넣기 할 때 [ Ctrl + Shift + V ] 단축키 사용
  - 서식(Style)을 모두 제거하고 순수 텍스트만 0.1초 만에 붙여넣어짐.


==================================================
[Java] 기본 타입 vs 참조 타입의 메모리 동작 요약
==================================================

1. 기본 타입 (Primitive Type)
  - 종류: int, double, boolean, char 등
  - 저장 위치: 스택(Stack) 영역
  - 동작 방식:
    * 변수 공간에 '실제 데이터 값'이 직접 저장됨.
    * 예) int i = 3; 후 i = 0; 실행 시
      -> 힙(Heap) 영역은 전혀 사용하지 않음.
      -> 스택 영역의 'i' 변수 상자 안의 값이 3에서 0으로 직접 덮어씌워짐.

2. 참조 타입 (Reference Type)
  - 종류: 배열(Array), 클래스(Class), 인터페이스 등
  - 저장 위치: 
    * 스택(Stack): 객체의 메모리 주소값(레퍼런스) 저장
    * 힙(Heap): 실제 객체 데이터 저장
  - 동작 방식:
    * new 연산자로 힙 영역에 객체를 새로 생성하고, 스택 변수에는 그 주소만 저장함.
    * 예) int[] arr = new int[3]; 후 arr = new int[5]; 실행 시
      -> 힙 영역에 크기 5짜리 새로운 배열 객체 생성
      -> 스택의 arr 변수가 가리키는 주소값이 새 객체의 주소로 교체됨.

3.
-클래스이름: 첫번째 문자는 대문자로 시작
-변수,메소드 이름: 첫단어는 소문자로 표기하고 카멜표기법 사용
-상수이름: 이름 전체를 대문자로 표기


==================================================
[Java] Math.random() 난수(랜덤 숫자) 생성 핵심 정리
==================================================

1. 기본 동작 및 반환값
  - 0.0 이상 ~ 1.0 미만의 실수(double) 반환
  - 범위: 0.0 <= Math.random() < 1.0

2. 원하는 범위의 정수(int) 추출 공식 (★강조)
  
  (int)(Math.random() * 개수) + 시작숫자

3. 대표적인 실전 예시
  - 1 ~ 10 사이 정수 : (int)(Math.random() * 10) + 1
  - 주사위 (1 ~ 6)   : (int)(Math.random() * 6) + 1
  - 로또 (1 ~ 45)    : (int)(Math.random() * 45) + 1
  - 0 ~ 9 사이 정수  : (int)(Math.random() * 10)

4. 주의해야 할 흔한 실수 (괄호 위치!)
  - [X] (int) Math.random() * 10 + 1  -> 항상 1만 출력됨 (0 * 10 + 1)
  - [O] (int)(Math.random() * 10) + 1 -> 곱셈 전체를 괄호로 감싸야 함

==================================================
[Java] 변수의 생존 범위(Scope) 및 소멸 시점 정리
==================================================

1. 핵심 원칙 (중괄호 법칙)
  - 자바의 변수는 자신이 선언된 중괄호 { } 블록 안에서만 살아있음
  - 중괄호 { }가 닫히는 순간 변수는 메모리에서 완전히 소멸함!

2. 주요 구문별 변수 소멸 위치
  - if / else문 : } 만나는 순간 블록 내부 변수 소멸
  - for / while : } 만나는 순간 루프 내부 변수 소멸
  - try / catch : } 만나는 순간 try 또는 catch 내부 변수 소멸

3. try-catch 구문 사용 시 주의사항 (★자주 나는 에러)
  [X] 잘못된 예시:
      try {
          int answer = scanner.nextInt(); // try 블록 안에서 선언
      } catch(...) { ... }
      if (answer == 10) { ... } // 에러! try가 끝나서 answer를 못 찾음

  [O] 올바른 예시:
      int answer = 0; // try 바깥에서 미리 선언!
      try {
          answer = scanner.nextInt(); // 값만 입력받음
      } catch(...) { ... }
      if (answer == 10) { ... } // 정상 작동!

4. 해결 공식
  - try 블록 안에서 입력받아 "try 바깥에서도 써야 하는 변수"는
    반드시 try문 위(바깥)에서 미리 선언해 둔다.


==================================================
[Java] 문자열(String) 비교 권장 방식 정리
==================================================

1. 절대 쓰면 안 되는 방식 : == 연산자
  - [X] str1 == str2
  - 이유: 문자열의 '내용'이 아니라 '메모리 주소'를 비교함!

2. 기본 내용 비교 : equals() (★기본)
  - [O] str1.equals(str2)
  - 문자열의 진짜 글자 내용이 같은지 비교

3. NullPointerException 방지 비교법 (★강력 권장)
  - 변수가 null일 가능성이 있을 때 에러를 막는 법
  - [O] "기준문자열".equals(변수)
        예: "exit".equals(input)
  - [O] Objects.equals(str1, str2)

4. 대소문자 구분 없이 비교 : equalsIgnoreCase()
  - [O] str1.equalsIgnoreCase(str2)  //i도 대문자다!!!!
        예: "YES"와 "yes"를 같다고 판단
